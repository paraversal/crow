## Decisions
- The compiled search rules are cached per `Ui::exclude_generation` and shared as `Arc<RuleSet>`; `Query.rules` is the `Arc`. The generation already bumps when `exclude.toml` changes, so a reload recompiles. — the `sample` of the 66.1 ms `Type` showed `RuleSet::from_config` → `globset` → `regex_automata` (14 ms) on the main thread every `start_search`; the engine cloned the `RuleSet` again per search. — finding from step 1's method.
- Display names are cached per thread, 512 paths, cleared when full. A renamed folder or volume changes the path, so its entry stays valid; a localized name change for the same path stays stale until eviction or restart. — cause (profile: 40–50% of busy time); the alternative was storing the name in every view.
- `selected_entries` (the drag payload) is invalidated by selection changes, not by every apply: a sort with a 100k selection can leave the payload in the old order until the next selection change. The set is exact. — cause; no user-visible behavior depends on the order.
- The apply's rows land one frame after its entries. Every row consumer (`row`, `selected_entries`, `prune`, `settle_cursor`) uses `get`, so a stale row is blank for one frame, never a panic; `rename_when_present` now waits for the row so its field has somewhere to focus. — plan ("a one-frame delay ... is fine").
- `--pause-ms` is a new runner option: `--until N` alone pauses before the step, so no sampler could see the step itself. — tooling for step 1.
- Bulk = more than 10 000 paths, read before the step (select-all uses the listing size, paste the clipboard, undo/redo their record, everything else the selection). Its budget is 100 ms; the run still fails only on a 250 ms freeze. — plan.
- `execute`'s callback now gets `(&Arc<Record>, Option<&OpError>)` instead of `&Outcome`, so the record moves into the log instead of being cloned. — cause (a 100k record clone per operation).
- Branch `m7-h4-6` from `main` @ b828a15 (batch 5 merged). — plan.
- Step 4's one-frame delay before a watcher change shows up is fine; 50 ms limit for scroll/navigation/typing/single-item ops, 100 ms for 100k bulk ops. — user, 2026-11-16 (plan "Decided").
