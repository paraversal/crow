## Why
H1 fuzzes a tidy fixture on a still disk. Real folders have 255-byte names, NFD twins, emoji, symlink loops and unreadable children, and they change while shown: downloads land, builds rewrite folders, another app trashes the file under the cursor. X7 (`done/u7-fix.md`) was a watcher race. H2 gives the fuzzer that world.

## Items

### I1 `crow_fs::testing`
**Change:** a `testing` cargo feature on `crow-fs` with `EdgeTree` (a list of edge kinds) and `make_tree(root, &EdgeTree, seed)`. Kinds:
- `LongName` (255 bytes in UTF-8, plus one at 255 bytes made of 3-byte chars), `NfcNfdTwins` (`café` NFC and NFD side by side; on APFS both can exist), `Emoji`, `Rtl` (Hebrew/Arabic, with a bidi override char), `LeadingDot`, `Spaces` (leading/trailing), `Newline` (a name containing `\n`), `Deep(n)` (20 levels), `Wide(n)` (100k entries, reusing the fixture writer), `SymlinkLoop` (`a → b → a`), `DanglingSymlink`, `Unreadable` (mode 000 folder and file), `Package` (`X.app` folder), `Hardlinks`, `EmptyFolder`, `HugeFile` (sparse 10 GB via `set_len`).
- Move `--make-fixture`'s writer behind it, so the bench fixture and tests share one generator.
- Cleanup restores permissions before deleting (mode 000 folders otherwise survive `remove_dir_all`).
**Tests:** `make_tree` builds each kind; listing each with `crow_fs` returns the expected count and doesn't error the whole folder for one bad child.

### I2 Churn
**Change:** `Churn::start(dir, seed) -> ChurnHandle` spawns a thread that, at random intervals (1–50 ms), creates, renames, deletes, rewrites, `chmod`s and moves files and folders in `dir` (and one level down), including the item the fuzzer most likely has selected (pick names from the current listing). Drop stops it and joins. `ChurnHandle::pause()` / `resume()` so `Settle` can wait for a quiet disk before invariant 6 compares listing and disk.
**Fuzzer:** H1's runner takes an option `churn: bool`; `fuzz_long` turns it on for half its runs. Add steps `Step::DeleteShownFolder` and `Step::ReplaceShownFolder` (delete and recreate with different contents) at low weight.
**Tests:** a churn run of 2 s on a 1k tree, then settle: listing equals disk (this is H1's invariant 6 on purpose).

### I3 Runs
Run `fuzz_long` with each edge kind and with churn, 30 minutes total at least. Findings → `findings.md` (shrunk scripts must include the tree kind and whether churn ran; churn makes replay nondeterministic, so also try the shrunk script without churn and note whether it still fails). Don't fix app bugs here; that's H4.
