## Decisions
- Branch `m7-h4-4` from `main` @ 768a7f4 (H4 batches 1–3, H5–H7 merged). — plan.
- Settings fonts: CoreText instead of AppKit `NSFontManager`. `objc2-core-text` and `objc2-core-foundation` are already in the lockfile (transitive), so this adds two direct dependency lines, not a new crate. The enumeration runs in `background_spawn`; the window shows System + the current family until the list lands. — cause + no main-thread AppKit work.
- Palette: the lowercased name is computed once when the parent lists (`PathEntry`), not per keystroke. The listing keeps the same behavior (case-insensitive prefix, exact file first, folders before other files). — cause + code convention.
- Watcher batches: one apply at a time, with the changes that arrive meanwhile queued. This is the X7 H1 shape (keep at most one apply in flight and merge queued paths into the next run), applied at the folder level; it does not change what the listing shows after a settle. — cause.
- ⌘A needed no change: release measurement is 6.75 ms; the live 67.9 ms was the first paint. — measured.
- The 541 ms ⌘L and 1560 ms Settle did not reproduce on a fresh fixture; the original run's state was mutated by 1986 steps. The fresh live run is the verification, not a code change. — measured.
- Inactive windows: the live runner requires focus only in the active window (`check_invariants_with_focus`); the test fuzzer still requires it. An inactive window has no focus by design; this scopes the invariant, it does not weaken the active-window check. — cause + harness correctness.
- GPUI active-status error: a new `patches/gpui-active-status-missing-window.patch` logs the closed-window case at debug and skips the update. The user chose the patch over excluding window keys or filtering the message. — user (Q3).
- Remaining slow steps: the load drains to the latest staged partial and the reconcile queues its paths behind an in-flight apply; both are unmeasured by a live run. The user chose to finish and let the critique decide (Q4). — user.
