## Status
| Item | State | Notes |
| --- | --- | --- |
| I1 Quick Look crashes | done (this commit) | Cause: `QLPreviewPanel` loads its preview plugins on a nested run loop, and the panel calls sat inside a GPUI input handler (`handle.update` holds the `App` borrow). GPUI's 100 ms poll task then ran during that loop and `AppCell::borrow_mut` panicked, aborting the process. Fix: every panel call now runs from a fresh main-queue turn (`NSOperationQueue::mainQueue` + `RcBlock`), updates coalesce; a `QLPreviewPanelDelegate` forwards the arrows QL does not use to Crow as `MoveUp/Down/Left/Right` (the panel is key while open), Space stays QL's close key. Verified from the release bundle on a folder, text files, a PDF and a PNG: panel shows each, arrows move the selection, Space closes; no panic, no new crash report. |
| I2 Path bar segments don't navigate | done (this commit) | Cause: `render_path_bar` rendered plain text with no hitboxes or click handlers. Now each segment is a `Role::Button` with a hover background and an aria label; a folder navigates as a history step (clicking the folder you are already in does nothing), a selected file opens with `Pane::open_file`. Also replaced the per-segment `path.is_dir()` stat with the cursor entry's own `is_dir`. Test: `path_bar_segments_navigate_as_history_steps`. |
| I3 Column view Left at leftmost column | done (this commit) | Cause: `move_left` returned when `focused == 0`. Now it pushes the parent in as the new column 0, selects the folder we came from in it and adds a history step; at `/` it does nothing. Also: a pending `views.toml` reload (e.g. the write behind Cmd-3) used to re-apply the new leftmost folder's mode and could flip the pane to list — `apply_view` now leaves the mode alone while a multi-column chain is open. Test: `column_view_left_on_the_leftmost_column_goes_up`. |
| I4 List view expandable folders | done (this commit) | Approach: `Folder` now owns an inline tree — a flattened row list (`FlatRow::Own(index)` for its own entries, cloned entries for expanded children), one child `Folder` per open folder with a subscription, and `expand`/`collapse` that delegate to the folder that lists the row. Expansions are in memory only and cleared by `enter`, so navigating away collapses everything. Option-click sets `expand_all`, which cascades as child folders load. Sort and hidden-file changes propagate to open children; a child's `Changed` event rebuilds its ancestors' rows. Selection stays path-based but over visible rows, so Cmd/Shift selection, copy and trash span levels. Rows draw a disclosure triangle (role Button, aria label Expand/Collapse, `disclosure-<name>` debug selector); nested rows indent 16 px per level. Left/Right are bound for `FileList && !ColumnView`; Vim `h`/`l` now follow the same table. Tests: `list_view_expands_folders_inline`, `list_view_left_steps_to_the_parent_row_then_collapses`, `option_clicking_a_triangle_expands_everything_below`, `selection_and_trash_span_expanded_levels`; the Vim test's `l` step was updated to expand first. |
| I5 Favorite drag-down reorder | done (this commit) | Cause: the only drop target was the top edge of a row ("insert above"), so dragging down onto the next row was a no-op and the last position could not be reached; the border grew the row and shifted the rows below. Now each favorite row has two 13 px drop halves with a top or bottom 2 px line; the lower half inserts after the row, so moving down works and "below the last favorite" appends. Tests: core `move_down_one_and_onto_itself` (down by one, both halves of itself), GPUI `dragging_a_favorite_down_inserts_below_the_row`. |
| I6 Sidebar row flicker during folder drag | done (this commit) | Cause: the highlight was a `drag_over` style recomputed against the last frame's hit test on every paint, and the favorites' indicator added a border to the hovered row. The highlight is now this view's state (`Sidebar::drop_target`), computed from the pointer and the bounds captured at prepaint, so it changes only when the pointer enters another row or group title; rows no longer carry drag-over backgrounds. Every direct child's bounds are remembered by `on_children_prepainted` (1 px gaps snap to the nearest row). Test: `sidebar_drop_highlight_is_steady_while_the_pointer_stays_on_a_row` (row, repeated frames, another row, a group title, leaving the window). |

## Decisions
- Branch `m5-fix` from `m5-sidebar-settings-themes`, not `main`, because M5 is unmerged (#5) and every fix touches M5 code — user decided.
- Progress file committed before any code — execute-plan skill.
- Quick Look keeps the keyboard: the panel is key, but its delegate forwards the arrows it does not handle to Crow. Doing it the other way (refusing key status) did not work: the panel becomes key anyway.
- In a multi-column chain a `views.toml` reload no longer changes the view mode. Entering a folder can still switch to column view; the running chain is one session, as the user asked for I3.
