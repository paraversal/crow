## Decisions
- Own titled window, one scrolling page, 560 pt wide and 760 pt tall content (560×792 with the titlebar). The page scrolls; Tab scrolls the focused control into view. — Q1/Q2 — user.
- Inline theme list with live preview; no Apply to All Apps in the window. The picker keeps its Apply to All Apps. — Q3 — user.
- Font family is a list of installed families; `crow_macos::available_font_families` uses `NSFontManager`, which AppKit only answers on the main thread. It is called once when the Settings window opens, never on browser startup. — Q4 + AppKit constraint — user/code.
- Files section links to `sidebar.toml`, `views.toml`, `exclude.toml`; no editors. — Q5 — user.
- While `settings.toml` is broken, every writing control is disabled and the banner shows the file/line with "Edit settings.toml…"; the Files buttons stay usable. — Q6 — user.
- One-line descriptions for partly-applied settings. — Q7 — user.
- `show_hidden_files` is now global and persisted: the browser's ⇧⌘. updates `Ui.settings` and writes, and the settings window's switch updates every browser window. Previously the toggle was per-window and not saved. This follows the setting's meaning and keeps the window honest. — code/plan.
- The theme list commits on Tab/Shift-Tab and on close explicitly, in addition to the focus-out listener; focus-out listeners run during `Window::draw`, so relying on them alone made "leaving keeps the choice" timing-dependent. — code.
- Settings-specific actions (`Up`, `Down`, `Left`, `Right`, `Activate`, `FocusNext`, `FocusPrev`, `CloseSettings`) instead of reusing the browser's `MoveUp/MoveDown/…`; reusing them made `keys::binding_for` pick the Settings binding for browser key labels. — code.
- `TextInput` gained a unique element id (`with_id`) because the three steppers are visible at once; the old fixed `"text-input"` id collided.
- The plan's Finish says "commit and push"; the repo's `AGENTS.md`/`execute-plan` skill say the executing agent commits locally and stops at "Ready for critique", and the critic opens the PR. No push or PR from this branch. — repo rules.

## Found along the way
- `keys::binding_for` matches by keystrokes, not the binding's context, so two actions bound to the same key in different contexts can return the wrong key label. We avoided the collision by giving the Settings window its own actions; a proper fix is M7 H8 material. — left alone.
- `TextInput` used one fixed element id for every field; fixed here with `with_id` because the Settings window shows three steppers at once. — fixed in scope.
