## Questions

- Q1 (asked 2026-11-18, answered **A (user)**): per-item plugin-command availability in the native menu. GPUI validates a menu item by **action type** (`App::is_action_available`, `vendor/zed/crates/gpui/src/app.rs:2991`, `key_dispatch.rs:382`), and the macOS delegate passes only the action instance to that check (`vendor/zed/crates/gpui_macos/src/platform.rs:1571-1595`). One `PluginCommand` action type therefore enables/disables every plugin command together; the bundle spike confirmed Alpha and Beta enable/disable as a pair, and a root-level handler keeps them enabled while the `/` filter field has focus. Options: (A, recommended) small GPUI patch adding a default-true per-action `is_available(window, cx)` checked by `is_action_available`; (B) one action type per surface/class, no per-command greying; (C) rebuild the menu on focus/selection transitions (contradicts the plan; GPUI's action store appends on every rebuild); (D) leave items enabled and no-op after revalidation. **A** was chosen and landed as `patches/gpui-action-availability.patch`.
