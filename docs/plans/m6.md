# M6 — Filter, command palette, search

Audience: an implementing agent. Follow `.claude/skills/execute-plan/SKILL.md`; read `AGENTS.md` first.
Source of scope: Phase 1 plan, milestone M6 (budget 3–4 weeks). Branch `m6-filter-palette-search` from `main` after M5-fix merges (ASK otherwise). One PR. Progress file: `docs/plans/m6.progress.md`.

## Scope (from the plan)
1. `/` filters the focused pane, with the query and match count visible.
2. Cmd-K command palette and fuzzy go-to (frecency + `nucleo`).
3. Search panel: names and contents, results streamed through `crow-search`.
4. Exclusion rule sets from `exclude.toml`: dev sentinels on by default, others opt-in; skip counts listing every skipped folder; "Search everything" (Cmd-Shift-A).
5. Whole-disk name search through Spotlight.

## Ground rules (from AGENTS.md, restated because M6 is I/O-heavy)
- No disk I/O on the main thread. Walking, matching and reading file contents happen on background threads and stream results to the UI in batches (the M2 listing pattern: `crow-fs` streaming + GPUI `background_spawn` + poll/notify).
- Every new key behavior gets a GPUI keystroke test (`crates/crow-app/src/window.rs` tests; per-test temp config via `ui::init_for_tests`).
- New config file follows the existing pattern: documented default written on first launch, live reload via the config-dir watcher in `crates/crow-app/src/ui.rs`, errors shown in the status line, Crow's own edits via `crow_core::edit_toml` (keeps comments).
- Every interactive element has a role and an aria label.
- Cancel stale work: a new query cancels the previous walk/search (use an `Arc<AtomicBool>` or a generation counter like `operations.rs` does).

## Steps

### S1 `crow-search` engine (no UI) — `crates/crow-search`
- Deps: `ignore` (parallel walker), `nucleo` / `nucleo-matcher` (fuzzy), `grep-searcher` + `grep-regex` (contents), `globset` (already in the lock via crow-core).
- API (suggested; adjust and record the decision):
  - `RuleSet` from `exclude.toml`: named sets of globs plus **sentinel** rules (a folder is skipped when it contains a marker, e.g. skip `node_modules`, `target` when next to `Cargo.toml`, `.git` internals, `__pycache__`, `.venv`, `build`/`dist` beside a manifest…). Each set: `enabled` default; dev sentinels on, others off.
  - `search(root, Query { names: Option<String>, contents: Option<String>, rules: &RuleSet, everything: bool }, sink, cancel)` streaming `Hit { path, kind: Name | Content { line, text, ranges } }` in batches, plus a final `Summary { scanned, skipped: Vec<(PathBuf, rule name)> }`.
  - Fuzzy name scoring via nucleo; contents via literal or regex (ASK: regex by default or literal?).
  - Respect hidden files setting? (ASK.) Respect `.gitignore`? (ASK; `ignore` does by default.)
- Unit tests on temp trees: rules and sentinels skip and are counted; cancel stops quickly; streaming order is stable enough to assert sets; content hits report correct line/ranges; binary files skipped.
- Bench: a large tree (make a fixture command like `--make-fixture`, e.g. 200k files in nested dirs); record time to first hit and total in `docs/testing.md`.

### S2 `exclude.toml` — `crates/crow-core`
- Model + documented default + loader like `views.rs` / `sidebar.rs`; reload live in `ui.rs` (add to `reload_config`, add an error slot).
- Default file documents each set and sentinel and how to enable/disable. ASK the user for the exact default sentinel list before finalizing.

### S3 `/` filter in the focused pane
- Bind `/` in `FileList` (both Finder and Vim layers; check it doesn't break type-to-select: type-to-select must not start on `/`).
- Filter applies to the focused folder (list: the list; columns: the focused column). Matching: case-insensitive substring or fuzzy (ASK; Finder has no equivalent). Query and "n of N" shown visibly (e.g. a field above the list or in the path bar's status area) and spoken by VoiceOver.
- Esc clears the filter; Return opens/moves into the selection; arrows move within the filtered rows; filter clears on navigation (ASK whether it should persist per folder).
- Selection, drag-out, copy/trash act on visible (filtered) rows only.
- Must interplay with M5-fix's expandable list rows (filter children too? ASK).
- Perf: filtering 100k rows must not drop frames; do it off the main thread if > a few ms, keep the last result while computing.

### S4 Cmd-K command palette + fuzzy go-to
- Overlay like the theme picker in `window.rs` (key context `Sheet Palette`, arrows/Return/Esc, Vim j/k).
- Two kinds of items in one list (or a `>` prefix for commands, ASK): **commands** (every action with a title: build a registry from `actions.rs` with labels and current key bindings shown) and **folders** (go-to: favorites, Recent's frecency list from `Ui.recent` + zoxide, plus subfolders of the current folder; scored with nucleo, ties broken by frecency).
- Return runs the command / navigates; Cmd-Return opens the folder in a new tab (ASK).
- Tests: open, type, Return runs a command (e.g. toggles hidden files); go-to navigates to a recent folder.

### S5 Search panel (names and contents)
- Cmd-F (Finder's key) opens a search field scoped to the current folder (scope switch: this folder / home / everywhere-with-Spotlight). Results stream into a list view (reuse the list table: name, folder, kind, modified; content hits show the matching line).
- Visible summary: "n results · m folders skipped (rules)", clickable to list every skipped folder with the rule that skipped it.
- "Search everything" (plan says Cmd-Shift-A): searches with all rule sets off. **Conflict:** Finder uses Cmd-Shift-A for Go ▸ Applications; ASK which key to use.
- Results support the usual actions: open, reveal in folder (Cmd-R like Finder's "Show in Enclosing Folder" ASK), Quick Look, drag out, copy, trash.
- Cancel on new query and on close.

### S6 Spotlight whole-disk name search — `crates/crow-macos`
- `NSMetadataQuery` (or `mdfind -name` as a fallback, ASK) streaming results; the only AppKit/Foundation code stays in `crow-macos`.
- Used by the search panel's "everywhere" scope; results merge with the walker's.
- Note: Spotlight doesn't see excluded/unindexed volumes. Show that in the summary.
